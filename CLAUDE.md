# Laniakea

SwiftUI astronomy app for iPhone and iPad (iOS 18.5+, `TARGETED_DEVICE_FAMILY = 1,2`). The Xcode project is `laniakea-dev.xcodeproj`, scheme `laniakea-dev`, bundle id `laniakea.laniakea-dev`. App code lives in `laniakea-dev/`. Proprietary, all rights reserved (see `LICENSE`).

## What the app is

Five tabs (`UI/Views/ContentView.swift`, tinted orange):

- **Discover**: NASA and ESA news (Spaceflight News API) as full-screen stories, with AI-written versions of each story.
- **Atlas**: an interactive map of the universe from the outside in. Laniakea → galaxy groups → galaxies; Laniakea → Local Group (both halves, from the Local Volume Database) → Milky Way → star systems (exoplanet hosts and naked-eye stars) → their planets, or the Solar System (planets, dwarf planets; moons on each planet's card, to scale). Black holes on the Milky Way map (Sgr A*, X-ray binaries, Gaia BH1–3) and as badges on galaxies with measured central black holes. Every object sits at its real position, flat or in 3D, with optional measured-motion simulation. Laniakea also shows the Cosmicflows-4 flow lines, cosmic web and 3D boundary. Fact sheets for every level. The camera button opens the Sky view.
- **Sky view** (`UI/Views/Sky/`): camera AR. Naked-eye stars, planets (at their real magnitudes), the Moon (at its phase) and the Sun drawn where they are in your sky from location + Core Motion attitude, a reticle that picks or locks an object, a corner mini-map of where it sits in Atlas, and a facts panel.
- **Home**: NASA Astronomy Picture of the Day with an AI write-up.
- **Settings**: global switches (see Design conventions).
- **Info**: credits for every data source (some licenses require it).

## Architecture

Clean layering under `laniakea-dev/`:

- `Core/` is pure Swift: only `Foundation` and `simd`, no SwiftUI/UIKit, no networking.
  - `Core/Entities/`: models (`Cosmos.swift` for groups, galaxies, star systems, exoplanets, naked-eye stars, Laniakea map; `Planet`, `FactHeader` + `CelestialPhotos`, article/APOD models).
  - `Core/Astronomy/`: the math (`LocalSky`, `SkyCoordinates`, `OrbitalElements`, `StarColor`, `PlanetComposition`, `PlanetMagnitude`, `SpaceMotion`, `CosmicFlow`, `MoonSky`, `Constellations`, `ConstellationChart`).
  - `Core/Repos/`: repository protocols (`CosmicRepo`, `PlanetRepo`, …).
- `Infrastructure/` implements the repos (networking, parsing, caching). Depends on Core only.
- `Interactors/`: use cases for the news/APOD/article flows.
- `UI/`: `ViewModel/` (`ObservableObject` view models, owned with `@StateObject`, passed down as `@ObservedObject`; never created inside `body`) and `Views/`. Depends on Core and Infrastructure.
- Dependency direction: UI → Infrastructure → Core. Core never imports anything above it.

### One data layer: `CosmicCatalog`

`Infrastructure/Catalog/CosmicCatalog.swift` (`CosmicCatalog.shared`) is the single front for all astronomy data:

- Sources, all public APIs: CDS VizieR and SIMBAD and the NASA Exoplanet Archive via ADQL (`TAPClient.swift`, CSV), JPL Horizons (`HorizonsPlanetAPIService.swift`, requests must be sequential: Horizons returns 503 to parallel ones), the Dupuy & Courtois 2023 basins-of-attraction grid by HTTP range request (`LaniakeaBoundarySource.swift`), the Cosmicflows-4 velocity and density fields (`CosmicFlowSource.swift`), Gaia DR3 (VizieR and the Gaia archive), the Local Volume Database release CSV, the IAU-CSN star names list, NASA Image Library photos and CDS hips2fits DSS2 cut-outs (URLs built in `Core/Entities/FactHeader.swift`, loaded with `AsyncImage`).
- Every result goes through `cached(_:maxAge:fetch:)` with a `DiskCache` (JSON in the Caches directory): fresh cache → fetch and save → stale cache fallback, so visited places work offline.
- Every cache name is versioned (e.g. `laniakea-map-v8`, `naked-eye-stars-v4`, `exoplanet-hosts-v5`, `local-group-v2`, `laniakea-flow-v2`). **Bump the version in the name whenever a query or parse changes**, or users keep the old data.
- Empty results throw (`nonEmpty`, `CatalogError.unreadable`) instead of being cached: an empty list means the query broke.
- No hardcoded or bundled astronomy data (Resources holds only `Assets.xcassets`), no own backend, and no dependency on GitHub Actions for data. Approved exceptions, each cited where it lives: the 88 constellation names (`Constellations.swift`), curated NASA photo IDs (`CelestialPhotos`), and black-hole values published only in papers (`Infrastructure/Catalog/BlackHoleReferences.swift`: Sgr A* distance and mass from GRAVITY 2022, M87* mass from the EHT, Gaia BH masses, Cyg X-1). Add new data through `CosmicCatalog`, not a new service called from a view.
- Separate from this: the AI articles are static JSON pre-generated by `generator/generate.py` and served from GitHub Pages (`GeneratedArticleAPIService`); they are never generated on device.

## Where things live

- Atlas shell: `UI/Views/AtlasView.swift`: `AtlasChrome` layout constants, `PlaceControl` (back + path menu, top left), `RoundButton`, `TimeControls`, `FilterSheet`, the `atlasGlass` modifier.
- Graph levels: `UI/Views/Atlas/CosmicGraph.swift` (`AtlasPlace`, `GraphNode`, `GraphScene`, `GraphBuilder`), `CosmicGraphView.swift` (gestures, selection, labels, scale bar), `AtlasFilter.swift`, view model `UI/ViewModel/CosmosViewModel.swift`.
- Solar System: `UI/Views/Atlas/SolarSystemView.swift` (`Canvas` + `TimelineView`, `TiltCamera` flat ↔ 3D), `SceneSpace.swift` (evenly spaced orbits, true directions; labelled "Not to scale"), `SimulationClock.swift`, `SolarSystemViewModel`.
- Exoplanet systems: `ExoplanetSystemView.swift`. Fact sheets: `FactSheets.swift`, `FactSheetView.swift`, `FactHeaderView.swift`, `PlanetDetailSheet.swift`, `FactSheetViewModel`.
- Sky view: `SkyView.swift`, `SkyPanels.swift` (facts panel, corner map), `SkyProjection.swift` (pinhole with the camera's real field of view, aspect-fill crop), `CameraPreview.swift`, `SkyStarRenderer.swift`; data and sensors in `UI/ViewModel/SkyViewModel.swift` (`SkyPointing` is read per frame, not published).

### Rendering split

- **Metal for bulk objects.** `GraphRenderer.swift` draws a `GraphScene` (Laniakea's region fill/edge, links, every glow/dot/ring) in a few instanced draw calls; buffers are rebuilt only when content, filter or selection changes. `SkyStarRenderer.swift` draws the naked-eye stars with one matrix per frame: `LocalSky.fromJ2000` (precession + turn to the horizon, recomputed once a second) times the camera.
- **Shaders are compiled at runtime** from the source string in `GraphShaders.swift` (`device.makeLibrary(source:)`, cached), so building needs no Metal toolchain. The Swift structs (`UniformsData`, `SpriteData`, `SegmentData`, `RegionQuadData`, `SkyUniformsData`, `SkyStarData`) **must match the shader structs (`Uniforms`, `Sprite`, `Segment`, `RegionQuad`, `SkyUniforms`, `SkyStar`) field for field**, including order and alignment. Change both together.
- **SwiftUI for everything else**: labels, overlays (planets, Sun, names, reticle in the sky view), hit-testing, the Solar System `Canvas`.
- **Cameras are classes moved by gestures without SwiftUI state** (`GraphCamera`, `SkyPointing`, the reticle state), so moving never rebuilds views. Labels are laid out once the map comes to rest and hidden while it moves. Hit-testing uses the same projection as drawing.

## Accuracy rules

- The astronomy must match the scientific literature; the owner looks things up. Cite the source (paper or catalog) in the doc comment of any formula or threshold.
- Verify against known objects before calling something done: astropy for coordinates (LocalSky is checked to ~0.01°), JPL Horizons for planet positions and constellations (quantity 29), published values for named stars and planets.
- Say what the catalogs can't cover (e.g. Cosmicflows only has galaxies with measured distances; no catalog lists stars in other galaxies; no exoplanets are confirmed outside the Milky Way). Mark estimates `≈` and minimums `≥`, and say whether a value is measured or estimated.
- No artist impressions. Headers are real photos (NASA Image Library with NASA's credit, DSS2 via hips2fits) or honest to-scale drawings from data, labelled as such; sizes estimated from mass get a dashed edge.
- Conventions in code:
  - Frames: groups/galaxies in supergalactic Cartesian **Mpc**, Milky Way at the origin; stars in galactic Cartesian **parsecs** (x to the Galactic Centre, z to Galactic north); local sky in Core Motion's `xTrueNorthZVertical` (**x north, y west, z up**); star directions in J2000 equatorial, precessed with IAU 1976; GMST from Meeus eq. 12.4; refraction ignored.
  - `StarColor`: B−V → temperature with Ballesteros 2012, one shared temperature color scale from Laniakea down to the Sun (groups take their brightest galaxy's color, galaxies use RC3 B−V or their Hubble type's median, the Sun is 5,772 K, unknown is grey). Batched drawing uses `StarColor.binEdges` (3,300 … 20,000 K) and `color(bin:)`.
  - `PlanetComposition`: rocky = brown, gas/ice-rich = blue. Solar System by density ≥ 3 g/cm³. Exoplanets: measured radius and mass vs pure-rock radius R ≤ 1.07·M^(1/3.7) (Zeng 2016); else radius < 1.6 R⊕ (Rogers 2015); else mass < 2 M⊕ (Chen & Kipping 2017). Masses or radii the archive derived from the other are ignored; Msini can only prove rocky.
  - Velocities are shown as seen from the Sun, not the CMB frame. Planet counts per host come from `count(*)` by `hostname`, not `sy_pnum`.
  - VizieR's Cosmicflows-4 group table has wrong sky positions for some groups; groups are placed from their members. Its row 1PGC 5064336 is the Milky Way's group (Kourkchi & Tully 2017); group 2557 is Andromeda's half. Both fold into the Local Group node on Laniakea.
  - The Local Group is in supergalactic **kpc** from the Sun, with the Milky Way at Sgr A*; members are confirmed galaxies within the 1.18 Mpc zero-velocity radius.
  - Distances from parallax need an error under 20%. Exoplanet hosts without `sy_dist` fall back to the archive's parallax, then Gaia DR3, then SIMBAD. Bright Star Catalogue stars match Hipparcos by HD number plus position. Recurrent novae listed at outburst brightness are dropped from the naked-eye list.
  - Gaia binaries use the `nss_two_body_orbit` parallax, not `gaia_source`.

## Design conventions

- Dark, minimal "glowing dots" look (data-viz, not textured planets). Maps stay dots; photos belong in fact-sheet headers.
- Orange accent. "You are here" and selection are an orange ring, the `here` color: `Color(red: 1.0, green: 0.69, blue: 0.36)` in dark mode, `(1.0, 0.48, 0.10)` in light. Supports light and dark.
- Floating controls over a full-screen map, sized by `AtlasChrome` (`cornerButton` 44, `bottomInset` 64, `bottomGap` 10, `searchFieldHeight` 56, `panelTop` 60, `panelBottom` 64). Use `RoundButton` and `.atlasGlass(shape)`: Liquid Glass (`glassEffect(.regular.interactive())`) on iOS 26, `.regularMaterial` with a hairline stroke before.
- Sheets use detents (`[.medium, .large]` on iPhone; fact sheets `.large` on iPad).
- The Settings tab holds global switches as `@AppStorage` keys, read with the same key where used. Existing: `sky.showsCamera`, `sky.showsMap`, `sky.showsFacts`, `sky.showsLock` (default `true`, used in `SkyView`); `atlas.simulations` (default `false`); `atlas.showsFlow`, `atlas.showsWeb`, `atlas.showsBoundary` (default `true`).
- User-facing copy: plain words, sentence case, short. Explain what's measured vs estimated and where data comes from.
- When a look is undecided, the owner likes a style board of options to pick from.

## Code style

- Match the surrounding code. Doc comments say *why* in plain sentences, not what the next line does.
- Swift 5 language mode (`SWIFT_VERSION = 5.0`): regex literals must be written `#/…/#`.
- Xcode synchronized folders: new files under `laniakea-dev/` are picked up automatically; don't edit `project.pbxproj` to add files.
- No Info.plist file: it's generated from `INFOPLIST_KEY_*` build settings (e.g. `NSCameraUsageDescription`, `NSLocationWhenInUseUsageDescription`). Add keys there, in both Debug and Release.

## Build and run

The owner tests on the physical iPhone by default.

```sh
# iPhone (default)
xcodebuild build -scheme laniakea-dev -configuration Debug -destination 'id=00008150-000410692640401C' \
  -derivedDataPath /tmp/laniakea-build-phone -allowProvisioningUpdates
xcrun devicectl device install app --device 00008150-000410692640401C \
  /tmp/laniakea-build-phone/Build/Products/Debug-iphoneos/laniakea-dev.app
xcrun devicectl device process launch --device 00008150-000410692640401C --terminate-existing laniakea.laniakea-dev

# Simulator (iPhone 17 Pro)
xcodebuild build -scheme laniakea-dev -configuration Debug -destination 'id=29438336-CB1A-4F05-B2B9-57045BF5D7E8' \
  -derivedDataPath /tmp/laniakea-build
```

- The simulator can't drag or fake device motion; the sky view falls back to drag-to-look there, and motion, camera and gestures need the phone.
- The app can't open on a given tab or screen. For screenshots, make temporary edits marked `// TEST-HOOK` and remove them before committing: `grep -rn "TEST-HOOK" laniakea-dev` must come back empty.
- Never commit secrets. `.env` is gitignored; load it inside scripts (e.g. Python reads it), never `source` it in a shell that echoes.
